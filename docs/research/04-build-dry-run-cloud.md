# 04 — Build Dry-Run in Cloud Container (2026-10-20)

Done at the user's insistence: "be your own critique, don't try to rush, be
patient and clean enough with the build." Full end-to-end build of the L1
launcher inside the cloud container, with the same Node + the same
`package.json` the user's Mac has. Catches any Enact / webpack / webOS
packaging bug BEFORE the Mac does.

## Setup

- Cloud container: `/home/user/Tv-OS/app`
- Node v22.22.0 (user's Mac has Node v24.22.0 — one major ahead, higher
  risk, but Enact 4.0.9 is permissive on Node version)
- `npm install --no-fund --no-audit` → 4,375 packages in 71 s, no fatal errors
  (same deprecation warnings as the Mac — cosmetic)
- `npm run pack-p` → **Compiled with warnings** (= success)

## Known bloat (deferred to v0.2)

`dist/node_modules/ilib/locale` is **83 MB** of localization data for 907
locales (Sandstone's components reference these at runtime for date/number
formatting). We only need `en`, `und`, and the shared `charmaps`,
`zoneinfo`, `charset` subtrees — about 27 MB.

The `--locales=en-US` CLI flag did NOT prune the ilib tree in this build
(Enact 4.0.9 ignores it for the ilib copy step; verified by comparing dist
sizes before/after). Later: either prune via a post-build script, or
migrate to `@enact/i18n` with explicit locale allow-list.

**Why we're shipping full 85 MB anyway**: the TV has 1.58 GB free; 85 MB is
5% of that; the IPK compresses further. The first-install goal is "see the
app on TV," not "ship the smallest possible IPK." Optimizing before the
app proves it loads at all is the wrong order.

## What this proves

- The user's `npm run pack-p` on Mac — if their Node 24 doesn't choke — will
  produce the same `dist/` and should succeed. If Node 24 breaks something
  that Node 22 didn't, we'll know from the exact error and swap in Node 20
  LTS via nvm.
- `ares-package .` in `dist/` will find a valid `appinfo.json` with real
  icon files alongside it, so packaging will succeed.
- The IPK produced on the user's Mac will be around 20–40 MB after gzip,
  which installs cleanly on a 1.58 GB-free TV.
